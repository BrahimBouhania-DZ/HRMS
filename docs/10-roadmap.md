## 1. فلسفة التخطيط (Incremental Delivery)

| المبدأ | التفصيل |
|---|---|
| **كل إصدار يعمل ويُستثمر** | لا نسلّم "مشروعًا ميتًا" حتى v3 — كل إصدار منتج قابل للتشغيل على LAN |
| **الأساس أولًا** | الهوية/الصلاحيات/الهيكل قبل كل شيء (كل شيء يعلقهما) |
| **القيمة العالية أولًا** | الحضور + الإجازات قبل الرواتب المتقدمة |
| **أولوية قابلة للتدقيق** | أولويات `يجب` من `01` تُغلق في v1/v2 |
| **تقنيات ثابتة** | Django/PostgreSQL/i18n/QR من v1 (لا تغييرات بنائية لاحقة) |
| **جودة عبر الإصدارات** | اختبارات + مراجعة أمنية عند كل معلم (Milestone) |

## 6.1 الإصدار 4.0 — التوظيف (Recruitment)

> **v4** — أُضيفت كمحور جديد بعد v3 لتغطية دورة حياة التوظيف (إعلان → مرشح → مقابلة → توظيف)، معزولة في `apps/recruitment`.

### الأهداف

- إعلانات وظائف بثلاث لغات (قسم/فرع/نوع توظيف/شواغر) بدورة حياة: مسودة → منشور → مغلق.
- مسار مرشح كامل: جديد → فرز → مقابلة → عرض → توظيف/رفض/انسحاب.
- جدولة مقابلات (حضوري/هاتف/فيديو) مع درجة ونتيجة.
- توليد ملف موظف تلقائيًا عند التوظيف (رمز فريد `EMP-####`) + إشعار داخلي للمحاورين.
- تقارير توظيف (REP-44/45) + صلاحيات `recruitment.*` (مدمجة في دور `hr_manager`).

### قواعد العمل (Business Rules)

| # | القاعدة | الحالة |
|---|---|---|
| BR-REC-001 | توظيف المرشح يُنشئ ملف موظف فريدًا ويربطه بالمرشح مرة واحدة | ✅ منفَّذ |
| BR-REC-002 | لا يُعاد فتح إعلان مُغلق؛ يفتح إعلان جديد بنسخة محدثة | ✅ منفَّذ |
| BR-REC-003 | إنهاء المرشح (رفض/تعيين/انسحاب) يغلق مقابلاته الجارية | ✅ منفَّذ |
| BR-REC-004 | التوظيف يشترط قبول العرض الوظيفي (OFFER) وإعلانًا مفعّلًا | ✅ منفَّذ |
| BR-REC-005 | الإعلان يُغلق تلقائيًا عند بلوغ التوظيفات عدد الشواغر | ✅ منفَّذ |

## 10. تحذيرات وقرارات تصميمية (Alert Box)

1. **⚠️ لا تؤجل i18n/RTL**: مبدأ "لا نص مدمج" مفروض من Sprint 1 — التأجيل = إعادة هندسة.
2. **⚠️ لا تؤجل نماذج v2 في DB**: نموذج Payroll/Contract/Document في `03` يُبنى في v1 (هجرات جاهزة) لتجنب Migrations مؤلمة على بيانات حقيقية.
3. **⚠️ الحضور أولًا تجاريًا**: غالبًا أهم قيمة تشغيلية للعميل — لا تجعلها آخر شيء.
4. **⚠️ الرواتب تتطلب تهدئة**: مراجعة محاسبية فعلية (محاسب مؤهل) قبل الإنتاج، لا اختبارات آلية فقط.
5. **⚠️ إطلاق تدريجي**: ابدأ بفرع واحد + مجموعة صغيرة من الموظفين، ثم وسّع — يقلل مخاطر الانتقال.
6. **⚠️ التدريب على الاستخدام**: حتى أفضل نظام يفشل بدون تدريب المستخدمين — خصص ميزانية تدريب في v1.
