## 1. الفلسفة: AI جزء من منطق النظام

| الفكرة | التفصيل |
|---|---|
| ليست "دردشة عامة" | المساعد لا يعرف شيئًا عن العالم — يعمل على **بيانات النظام فقط** |
| **موجّه بالبيانات** | كل إجابة تُبنى على استعلامات حقيقية على قاعدة البيانات داخل نطاق صلاحيات المستخدم |
| **قابل للتصرف** | كل نتيجة (تحليل/تنبؤ) يمكن تحويلها لإجراء: تقرير، إشعار، PIP، تنبيه مشرف |
| **لا يكتب** | قراءة فقط (Read-Only): لا يعدّل ولا يحذف أي بيانات |
| **محلي** | يعمل داخل LAN: لا إرسال بيانات إلى أي سحابة |

### دور النظام الذكي (منطق مدمج)

```
تحليلات دورية (جدولة) → رؤى (Insights) → إشعارات ذكية → اقتراحات
     ▲                                                        │
     └──────── سؤال/أمر من المستخدم (NL) ←────────────────────┘
```

### قرارات تنفيذية

| الخيار | القرار | المبرر |
|---|---|---|
| **نموذج اللغة (LLM)** | محلي: **Ollama + Llama 3 / Qwen (Arabic)** إن كانت الأجهزة تسمح، أو **منطق قالب-محرك (Template NL)** بدون LLM في v1 | لا إنترنت + خصوصية + تحكم كامل. يُبنى الواجهة مجردة لاستقبال أي "Backend لغوي" |
| **التحليلات** | خوارزميات Python + SQL (ليس شبكة عصبية معقدة) | دقة وقابلية تدقيق وتفسير |
| **التنبؤ** | نماذج تعلّم آلي خفيفة: Random Forest / Logistic Regression / XGBoost (على خصائص محسوبة) | قابلة للتدريب محليًا وتفسيرها (SHAP) |
| **التنفيذ** | مهام Celery + تخزين النتائج | التقارير الثقيلة خلفية |
| **الإصدار 1.0** | Analytics + Assistant (قالبي) + تنبؤ أساسي | قابلية النجاح قبل تعقيد النماذج |

## 3. طبقة التحليلات (Analytics Engine)

> مجموعة **محلّلات** مبنية على مؤشرات قابلة للقياس، لا تخمين.

### 3.1 مؤشرات الحضور والغياب

| المؤشر | الصيغة/المصدر |
|---|---|
| نسبة الحضور اليومية | حاضرون ÷ مستهدفون × 100 |
| معدل التأخر | مجموع دقائق التأخر ÷ عدد الأيام |
| معدل الغياب | أيام غياب ÷ أيام العمل × 100 |
| غياب متكرر (Pattern) | موظف يغيب في أيام/فترات معينة (تحليل توزيع) |
| الإنتاجية الزمنية | ساعات فعلية ÷ ساعات مستحقة |
| العمل الإضافي | مجموع دقائق OT حسب القسم/الفترة |

### 3.2 مؤشرات الرواتب

| المؤشر | الوصف |
|---|---|
| توزيع الرواتب حسب القسم/الفرع | مقارنات داخلية |
| تكلفة العمل الإضافي | دقائق OT × المعدل — بفترة |
| فروق الرواتب الشاذة | انحراف عن متوسط القسم |
| نمو كتلة الأجور | مقارنة شهرية |

### 3.3 مؤشرات الأداء

- توزيع درجات التقييم حسب القسم.
- الموظفون الأقل أداءً (تحت الحد) → اقتراح PIP.
- موظفون متجاوزون للتوقعات → اقتراح مكافأة (يُقدَّم كمقترح للمدير).

### 3.4 التخطيط للقوى العاملة

- عبء العمل المتوقع حسب الموسمية (من بيانات تاريخية).
- توصية تغطية نقص قسم عند ارتفاع الغياب المتوقع.

## 4. المساعد الذكي (AI Assistant)

### 4.1 الأنواع المدعومة من الأوامر

| النوع | مثال |
|---|---|
| إحصائية | "كم موظفًا غائبًا اليوم؟" |
| تصنيف/ترتيب | "أعطِ أكثر 5 أقسام تأخرًا هذا الشهر" |
| تحليلي | "هل هناك نمط غياب في قسم الإنتاج؟" |
| تنبؤي | "ما احتمال استقالة فريق المبيعات؟" |
| تقارير | "أنشئ تقرير رواتب يونيو" |
| تنفيذي | "لخّص أداء الشركة لهذا الربع" |
| إجرائي (تعليمات) | "كيف أعتمد كشف راتب؟" → يوجّه خطوة بخطوة داخل النظام |

### 4.2 فهم السؤال (Intent + Entity Resolution)

```
سؤال المستخدم
   │
   ▼
1. توحيد النص (Normalize: أحرف عربية/فرنسية/إنجليزية + أرقام)
   ▼
2. كشف الهدف (Intent): attendance | leave | payroll | perf | report | ...
   ▼
3. استخراج الكيانات:
   • موظف (اسم/رمز)   • قسم   • فرع   • فترة (شهر/ربع/سنة/نطاق)
   • كمية (أعلى/أدنى/عد)   • عملية (عرض/تقرير/تنبؤ)
   ▼
4. تعيين النطاق (Scope) حسب صلاحيات المستخدم
   ▼
5. توليد SQL/استعلام آمن (مبيّن) + تنفيذ
   ▼
6. صياغة الإجابة باللغة المختارة + (جدول/مخطط/تقرير قابل للتصدير)
```

### 4.3 القواعد

| القاعدة | التفصيل |
|---|---|
| **الإجابة موثّقة** | كل إجابة تذكر مصدرها (فترة/قسم/عدد السجلات) |
| **استعلامات معلمة** | لا يتم بناء SQL من النص مباشرة — استخدام طبقة مرمّزة (mapping مسبق) لمنع الحقن |
| **عدم اليقين** | إن لم يفهم السؤال: يسأل توضيحًا بأسئلة اختيارية |
| **صفر تعميم** | لا يخترع أرقامًا — كل رقم من قاعدة البيانات |

## 5. التنبؤات (Prediction Engine)

### 5.1 تنبؤ مخاطر الاستقالة (Turnover Risk)

**خصائص الإدخال (Features):**

| الخاصية | المصدر |
|---|---|
| معدل الغياب والتأخر (آخر 6 أشهر) | attendance |
| عدد الإجازات المرضية المتكررة | leave |
| التقييم الأخير واتجاهه | perf |
| ترقية/زيادة (هل حصلت خلال 12 شهرًا؟) | jobhistory/payroll |
| مدة الخدمة | contract/employee |
| ساعات العمل الإضافي غير المكافأة | attendance/payroll |

**المخرجات:** `probability 0..1` + **العوامل المساهمة** (SHAP) + الفئة (منخفض/متوسط/مرتفع).

### 5.2 تنبؤ مخاطر الغياب (Absence Risk)

- توقع الأقسام/الأيام الأعلى غيابًا في الفترة القادمة (موسمية تاريخية).
- توقع الموظفين الأكثر عرضة للغياب غير المبرر.

### 5.3 دورة التدريب والتحقق

```
جمع عينات تاريخية (موظفون غادروا/بقيوا + غيابهم) → تدريب → تحقق (تقاطع K-Fold)
→ قياس (AUC, Precision/Recall) → تخزين النموذج + الإصدار → إعادة تدريب مجدولة
```

> **تحذير أخلاقي/عملي:** مخرجات التنبؤ **قرار مساعد لا إلزامي** — تُعرض كمقترحات لإجراءات إدارية (مقابلة، دعم، مراجعة) ولا تُستخدم لقرارات فصل أو خصم آلي.

## 10. دورة معالجة السؤال (Sequence)

```
المستخدم ── سؤال ──► واجهة AI ──► خدمة NL (Intent+Entities)
                                  │
                                  ▼
                          نطاق الصلاحيات (RBAC)
                                  │
                                  ▼
                          بناء الاستعلام (Parameterized)
                                  ▼
                          Analytics Engine / Prediction
                                  ▼
                     صياغة إجابة (AR/FR/EN) + مخرجات (جدول/رسم/تقرير)
                                  ▼
                          تسجيل ai_aiquery + إشعار (اختياري)
```

## 11. الأمان والخصوصية والصلاحيات

| البند | التفصيل |
|---|---|
| **صلاحيات** | `ai.assistant.use` + `ai.analytics.view` — ونطاق البيانات مثل أي وحدة (لا يتجاوزه) |
| **قراءة فقط** | لا توجد أي نقطة كتابة عبر AI |
| **خصوصية** | البيانات لا تغادر الخادم؛ لا سجلات مع أنظمة خارجية |
| **تدقيق** | كل سؤال في `ai_aiquery` (من سأل، متى، ماذا، ما النتيجة) |
| **الحقن** | بناء استعلامات عبر طبقة مبيّنة، لا من النص |
| **نموذج محلي** | لا اتصال خارجي — حتى خيارات "LLM" تُشغَّل عبر Ollama محليًا |
| **فصل الأدوار** | تنبؤات التقويم لا تُستخدم كأساس لعقوبات آلية (تقييد إداري) |

## 12. قياسات الجودة والاختبار

| الفئة | المعيار |
|---|---|
| دقة الفهم (Intent) | ≥ 90% على مجموعة أسئلة اختبار (بكل اللغات) |
| دقة التنبؤ | AUC ≥ 0.75 على بيانات تاريخية للمؤسسة (اختبار متقاطع) |
| صفر حقن | اختبارات أمان على طبقة الاستعلامات |
| الأداء | إجابة تحليل < 5 ثوانٍ؛ تقرير ثقيل < 60 ثانية (خلفية) |
| انحراف صياغة | مقارنة قوالب لكل لغة (اختبارات آلية للرسائل) |

## 14. تحذيرات وقرارات تصميمية (Alert Box)

1. **⚠️ لا تبدأ بـ LLM**: ابدأ بمحرك تحليلات (مؤشرات حقيقية) + مساعد قالبي؛ الـ LLM يضيف قوة صياغة لكنه **غير مطلوب** للقيمة الأساسية وقد يضيف مخاطر خصوصية وتعقيدًا.
2. **⚠️ القرارات الناتجة عن AI إدارية وليست آلية**: أي اقتراح (PIP/مكافأة/تنبؤ) يعرض على مسؤول بشري للاعتماد — تجنّب "قرار آلي" قانونيًا وعمليًا.
3. **⚠️ جودة البيانات قبل التنبؤ**: تنبؤ على بيانات متسخة يعطي قرارات مضللة — أدرج فحص جودة البيانات (اكتمال، تكرار) ضمن خط الأنابيب.
4. **⚠️ الحقن في الأسئلة**: لا تقم أبدًا بتجميع SQL من نص حر. طبقة mapping مسبقة إلزامية.
5. **⚠️ التوثيق والتفسير**: كل رقم يُنتج مع مصدره وفترته — شفافية تبني الثقة وتمكّن التدقيق.
