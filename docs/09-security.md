## 2. Authentication (المصادقة)

| البند | التفصيل |
|---|---|
| **الاعتماد** | اسم مستخدم + كلمة مرور (هيئة النظام)، MFA إلزامية للأدوار الإدارية |
| **MFA** | TOTP (رمز زمني 6 أرقام) عبر تطبيق مصادقة — تعويض فوري لانتهاكات الشبكة الداخلية |
| **القفل** | 5 محاولات فاشلة → قفل 15 دقيقة (قابل للضبط) + إشعار المسؤول |
| **استعادة كلمة المرور** | رمز استخدام-واحد (مرتبط بجلسة) عبر بريد LAN أو سؤال أمان + إبطال الرموز القديمة |
| **تغيير إجباري** | أول دخول + كل 90 يومًا (سياسة قابلة للضبط) + منع إعادة آخر N كلمات |
| **الخروج** | إبطال الجلسة + تحديث السجل |
| **رموز الأجهزة** | قارئات QR تصادق بمفتاح جهاز (API key hash) لا بجلسة مستخدم |

## 3. Authorization (التفويض)

- نموذج RBAC كامل مع نطاقات البيانات: `05-rbac.md`.
- **مبدأ أقل صلاحية** + **الفصل الوظيفي (SoD)**: لا يجمع نفس المستخدم بين "توليد" و"اعتماد" كشف الرواتب.
- كل طلب يمر عبر: جلسة → تفويض (صلاحية) → نطاق (بيانات).
- واجهة العرض لا تعتمد عليها أبدًا — التحقق في طبقة الخدمات.

---

## 4. Password Hashing (تجزئة كلمات المرور)

| البند | التفصيل |
|---|---|
| **الخوارزمية** | Argon2id (يُفضَّل) أو PBKDF2-SHA256 بتكرارات عالية — لا bcrypt/md5/sha1 مسطحة |
| **التخزين** | hash + salt فريد لكل مستخدم (إدارة Django PasswordHashers) |
| **لا تراجع** | التجزئة باتجاه واحد فقط؛ لا نصوص صريحة تُخزن أبدًا |
| **تحديث خوارزمية** | تدوير التجزئة عند تسجيل الدخول (إعادة hash بالخوارزمية الأحدث) |
| **التحقق** | مقارنة زمن ثابت (وقت متساوٍ) لمنع هجمات التوقيت |

---

## 5. Session Management (إدارة الجلسات)

| البند | التفصيل |
|---|---|
| **التخزين** | جلسات DB/Redis (قابلة للإبطال عن بعد — لا ملفات) |
| **المعرّف** | Session ID عشوائي آمن، ينقل عبر **Cookie آمنة HttpOnly + Secure + SameSite=Lax** |
| **انتهاء الصلاحية** | خمول 30 دقيقة (قابل للضبط) + انتهاء مطلق 12 ساعة |
| **القيود** | ربط الجلسة بـ IP (اختياري) + إبطال عند تغيير كلمة المرور |
| **إدارة من طرف المسؤول** | إنهاء جلسات المستخدم من لوحة الإدارة (طرد فوري) |
| **الخروج الشامل** | "الخروج من كل الأجهزة" + إبطال مفاتيح الأجهزة عند الشك |

## 6. Audit Log (سجل التدقيق)

| البند | التفصيل |
|---|---|
| **التغطية** | كل عملية كتابة (إنشاء/تعديل/حذف/اعتماد/رفض/مسح/دخول/خروج/تصدير حساس) |
| **الحقول** | actor (مستخدم أو "نظام"), IP, action, model, object_id, `field_changes` (قبل/بعد), request path, زمن (UTC) |
| **التمنيع** | سجل **append-only**: لا تعديل ولا حذف (حذف فعلي محظور بقاعدة DB) |
| **الربط** | `audit_auditlog` يلتقط حتى محاولات الفشل (رفض QR، قفل حساب، فشل دخول) |
| **التقارير** | REP-50/REP-52 (راجع `08`) + بحث بفلاتر |
| **الاحتفاظ** | أرشيف منفصل بعد N سنة دون حذف |
| **الاستثناء** | قراءة بيانات حساسة (فتح وثيقة سرية، عرض بنكي) تُسجَّل أيضًا كـ "قراءة حرجة" |

## 7. Backup & Restore (النسخ الاحتياطي والاستعادة)

| البند | التفصيل |
|---|---|
| **الأنواع** | كامل يومي (PostgreSQL `pg_dump`) + WAL archiving (اختياري للاستعادة اللحظية) |
| **الجدولة** | تلقائي يومي 02:00 + أسبوعي + يدوي (زر في الواجهة) |
| **المحتوى** | قاعدة البيانات + ملفات الوثائق + الإعدادات (النسخة تشمل كل شيء أو مقسمة — قابلة للتكوين) |
| **التشفير** | ملف النسخة **مشفّر** (AES-256) قبل مغادرته الخادم |
| **الوجهات** | محلي + **قرص/NAS ثانوي عبر LAN** + (اختياري) وسيط منقول للطوارئ |
| **التحقق** | checksum عند الكتابة + **اختبار استعادة شهري إلزامي** (يُسجل في `restorejob`) |
| **إشعارات** | نجاح/فشل → إشعار IT؛ فشل متكرر → تنبيه مرتفع |
| **الاستعادة** | واجهة استعادة من أي نسخة (اختيار + معاينة التاريخ) + قفل استعادة أثناء التشغيل |
| **الاحتفاظ** | سياسة تدوير (يومي × N يوم، أسبوعي × N شهر، شهري × N سنة) حسب احتياج الامتثال |

### إجراء الاستعادة (Restore Procedure)

```
1. إشعار النظام "وضع الصيانة" → إيقاف الوصول الكتابي
2. اختيار نسخة (قائمة + تاريخ)
3. إيقاف الخدمات المؤقت → استعادة DB + الملفات
4. تشغيل الفحوصات (تجزئة النسخة، عدّادات، عينات)
5. فتح النظام + تقرير نجاح/فشل (audit_restorejob)
```

## 8. Encryption (التشفير)

| الطبقة | التفصيل |
|---|---|
| **النقل (TLS)** | HTTPS داخل LAN بشهادة **Internal CA**؛ لا HTTP صريح للواجهات |
| **الحقول الحساسة** | تشفير AES-256 على مستوى الميدان (بيانات بنكية، هوية، جواز) — `django-encrypted-fields`/Fernet |
| **الملفات** | وثائق سرية مشفرة عند التخزين؛ تحميل/عرض يمر عبر بوابة تفويض |
| **النسخ الاحتياطي** | تشفير ملفات النسخ + مفاتيح منفصلة |
| **أسرار النظام** | SECRET_KEY، مفاتيح HMAC، مفاتيح تشفير → ملف `.env` محمي (600) خارج الكود، لا في Git |
| **إدارة المفاتيح** | مفاتيح منفصلة للمجالات المختلفة؛ خطة تدوير (Rotation) موثقة |

## 9. أمان الشبكة المحلية (LAN)

| الإجراء | التفصيل |
|---|---|
| **عزل الشبكة** | VLAN للخادم؛ لا وصول إنترنت عام إلا للصيانة عبر VPN (اختياري) |
| **جدار نار** | تقييد المنافذ؛ قاعدة: غير مصرح به مرفوض (فقط 443/80 للمتصفحات + 5432 للشبكة الداخلية المصرح بها) |
| **IP Allowlist** | قارئات QR مصادقة + تقييد شبكات مديرة |
| **لا تعريض للإنترنت** | النظام خدمة LAN فقط (خارج نطاق v1) |
| **شبكة WiFi** | WPA2/WPA3 + شبكة ضيوف منفصلة عن شبكة العمل |

## 10. أمان طبقة التطبيق (OWASP Top 10)

| التهديد | التخفيف في HRMS |
|---|---|
| **A1 الحقن** | ORM + استعلامات معلمة؛ عدم بناء SQL من النص (حتى أسئلة AI) |
| **A2 مصادقة مكسورة** | Argon2id، MFA، قفل، جلسات آمنة، إبطال |
| **A3 كشف بيانات حساسة** | تشفير حقول/ملفات، نطاق صلاحيات، تقليل سجلات |
| **A4 XML/Entity** | لا XML خارجي؛ بارس آمن للملفات |
| **A5 تحكم وصول معطل** | RBAC + Scope + SoD + اختبارات نطاق |
| **A6 تكوين خاطئ** | إيقاف Debug في Prod، رؤوس أمان (HSTS/CSP)، أذونات ملفات |
| **A7 XSS** | Escape كل مخرجات القوالب (Django autoescape) + CSP |
| **A8 CSRF** | Tokens لكل نماذج الكتابة + SameSite |
| **A9 مكوّنات معروفة الثغرات** | تحديث اعتمادات منتظم + فحص تبعيات (pip-audit) |
| **A10 مراقبة وفشل تسجيل** | Audit log كامل + مراقبة محاولات مشبوهة |

### حدود معدل (Rate Limiting)

- تسجيل الدخول، API المسح، تصدير التقارير: حدود معدل لكل IP/مستخدم.

## 12. أمان وحدة الذكاء الاصطناعي

- مساعد AI **قراءة فقط** وضمن نطاق صلاحيات المستخدم (لا وسيلة للتجاوز).
- استعلامات AI معلمة (لا SQL من النص).
- كل سؤال مسجّل في `ai_aiquery` (تدقيق كامل).
- نموذج LLM (إن فُعِّل) يعمل محليًا — لا اتصال خارجي؛ سياسة خصوصية صريحة.

## 13. أفضل الممارسات وقائمة فحص النشر (Security Checklist)

### إعدادات Django

- [ ] `DEBUG=False` في الإنتاج.
- [ ] `SECRET_KEY` من `.env` (غير مضمّن).
- [ ] `ALLOWED_HOSTS` = عناوين LAN المصرح بها فقط.
- [ ] رؤوس أمان: `SECURE_SSL_REDIRECT`، `HSTS`، `X-Frame-Options: DENY`، `CSP`، `X-Content-Type-Options`.
- [ ] Cookies: `HttpOnly` + `Secure` + `SameSite=Lax`.
- [ ] تقييد `MEDIA` بالتفويض (لا خدمة مباشرة للملفات السرية).
- [ ] إيقاف صفحات Admin الافتراضية العامة (منع كشف مسارها) أو حصرها بالشبكة.

### الإجراءات المؤسسية

- [ ] فصل صلاحيات (Admin ↔ HR Manager ↔ Accountant) دون تداخل يخالف SoD.
- [ ] اختبار استعادة شهري موثق.
- [ ] مراجعة دورية لسجل التدقيق (كشف الشذوذ).
- [ ] سياسة توعية: كلمات مرور قوية، عدم مشاركة الحسابات، إبلاغ عن QR مفقود.
- [ ] خطة تحديث اعتمادات ومراقبة ثغرات.

## 16. تحذيرات وقرارات تصميمية (Alert Box)

1. **⚠️ لا تثق بـ LAN**: "شبكة داخلية" لا تعني آمنة — الموظفون أنفسهم مصدر تهديدات (T2/T4). TLS + MFA + RBAC أساسية.
2. **⚠️ MFA للمسؤولين إلزامية**: حساب مسؤول مخترق = تعريض كل الرواتب — لا استثناء.
3. **⚠️ لا تكتب أسرارًا في Git**: `.env` مستثنى؛ مفاتيح التشفير منفصلة عن الكود.
4. **⚠️ النسخ الاحتياطي عديم القيمة بدون اختبار استعادة**: جدول شهرية لاختبار الفعلي.
5. **⚠️ التشفير الحقلاني ليس بديلًا عن RBAC**: التشفير يقي من "كشف ملف"، والصلاحيات تمنع "الوصول" — كلاهما مطلوب.
6. **⚠️ قانونية البيانات**: سجل الرواتب/التوظيف ≥ 7 سنوات؛ أرشفة تدعم ذلك دون حذف فعلي.
