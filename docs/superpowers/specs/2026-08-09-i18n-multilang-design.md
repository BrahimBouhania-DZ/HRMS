# تصميم: تدويل كامل (i18n) للواجهة — ثلاث لغات

التاريخ: 2026-08-09

## الهدف

تفعيل الدعم الكامل للغات في نظام HRMS: العربية (أصل النصوص) + الفرنسية + الإنجليزية.
تغطية شاملة لكل قوالب النظام (50 قالبًا) ووحدات بايثون (16 وحدة) مع مبدّل لغة
ودعم اتجاهات RTL/LTR ديناميكي.

## الوضع الحالي

- البنية معدة بالفعل في `config/settings/base.py`:
  - `LocaleMiddleware` مفعّل
  - `LANGUAGES = [("ar", "العربية"), ("fr", "Français"), ("en", "English")]`
  - `LANGUAGE_COOKIE_NAME = "hrms_language"` مع عمر سنة
  - `LOCALE_PATHS = [BASE_DIR / "locale"]`
- لا توجد ملفات `locale/` (فارغة)
- القوالب كلها نصوص عربية ثابتة (بدون `{% trans %}`)
- النماذج (models) وبعض `forms.py` تستخدم `gettext` جزئيًا
- الـ views لا تستخدم gettext إطلاقًا (52+ رسالة `messages.*` غير معرّبة)
- `base.html` مثبّت `lang="ar" dir="rtl"`

## القرارات

1. **لا مكتبات إضافية** — اعتماد خط أنابيب Django القياسي.
2. **العربية = msgid** — النصوص العربية تبقى كما هي كسلسلة مصدر، وتُترجم
   إلى الفرنسية والإنجليزية في ملفات `.po`.
3. **الترجمات تُكتب يدويًا** (دقة عالية، تعمل دون إنترنت على LAN).
4. **الاتجاه ديناميكي**: `dir="rtl"` للعربية، `dir="ltr"` للفرنسية/الإنجليزية
   عبر context processor يزوّد القالب بمتغير `LANGUAGE_DIR`.
5. **تنسيق التواريخ والأرقام** محلي تلقائيًا عبر `USE_I18N = True`.

## البنية والمكوّنات

### 1. Context processor جديد `apps/core/context_processors.py`
يوفر للقوالب:
- `LANGUAGE_CODE` (لغة نشطة)
- `LANGUAGE_DIR` = `"rtl"` للعربية و`"ltr"` لغيرهما
- `LANGUAGES` المتاحة لبناء مبدّل اللغة

### 2. `templates/base.html`
- `<html lang="{{ LANGUAGE_CODE }}" dir="{{ LANGUAGE_DIR }}">`
- إضافة مبدّل لغة في الشريط العلوي: نموذج POST إلى `{% url 'i18n:set_language' %}`
  مع قائمة منسدلة باللغات + زر أو تفعيل فوري.

### 3. مسار `set_language`
- `i18n` في `config/urls.py` لتوفير `i18n:set_language`.

### 4. القوالب (50 ملفًا)
- استبدال كل نص عربي ثابت بـ `{% trans "..." %}`.
- عند احتواء النص على متغيرات: `{% blocktrans %}...{% endblocktrans %}`.
- وسوم `title` كتلك في `{% block title %}` تُغلف بـ `{% trans %}`.
- نصوص الأزرار، الترويسات، الشارات، عناصر القوائم، رسائل التأكيد،
  رسائل الخطأ والفراغ، تلميحات الحقول.

### 5. بايثون
- الـ views: رسائل `messages.*` → `gettext()` (ولأنها تُنفَّذ لحظيًا لا مشكلة).
- `forms.py` / `models.py`: استكمال `gettext_lazy` حيث ناقص.
- نصوص معرّفات المسارات التي تظهر للمستخدم (مثل "أسبوع", "شهر") إن وجدت.

### 6. ملفات الترجمة
- `locale/ar/LC_MESSAGES/django.po` — قد نضعه كأصل مرجعي (اختياري).
- `locale/fr/LC_MESSAGES/django.{po,mo}`
- `locale/en/LC_MESSAGES/django.{po,mo}`
- تُنشأ بـ `makemessages --no-obsolete` وتُترجم وتُجمَّع بـ `compilemessages`.

### 7. CSS
- تجاوزات `html[dir="ltr"]` للجداول (`text-align: left`) والقوائم الوصفية
  لتقديم صحيح عند اتجاه LTR.

## تدفق البيانات

1. المستخدم يختار لغة من مبدّل اللغة.
2. `set_language` يحفظ الاختيار في cookie `hrms_language`.
3. `LocaleMiddleware` يفعّل اللغة حسب cookie في كل طلب.
4. القوالب/البايثون تعرض السلاسل المترجمة من `.mo`.
5. عند غياب ترجمة: السقوط تلقائي إلى العربية (msgid).

## معالجة الأخطاء

- لا توجد ترجمة لسلسلة → تظهر العربية (msgid) دون انهيار.
- لغة غير مدعومة في cookie → تُتجاهل وتُستخدم لغة الموقع الافتراضية.

## الاختبار

1. تحقق من سلامة كل القوالب (`get_template` للكل).
2. `makemessages --no-obsolete` بلا أخطاء.
3. `compilemessages` بنجاح.
4. عرض صفحات عينة (الرئيسية، الموظفون، الحضور، الدخول، التقارير) باللغات الثلاث.
5. التأكد من اتجاه الصفحة: rtl للعربية وltr للفرنسية/الإنجليزية.

## النطاق المستبعد (YAGNI)

- ترجمة محتوى قاعدة البيانات (أسماء الموظفين/الإدارات) — البيانات لا تُترجم.
- نظام fallback لأكثر من لغة افتراضية.
- ترجمة الرسائل داخل تقارير PDF النصية — تُترك للغة الجلسة الحالية فقط.
